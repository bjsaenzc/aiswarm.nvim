`:Hive*` commands and `bin/hive` forward to the aiswarm implementation.

==============================================================================
SETUP                                                              *hive-setup*

Requires Neovim 0.10.4+, snacks.nvim, and the bundled bin/hive backend. The
backend requires Bash 3.2+, jq, tmux 3.2+, and GNU timeout to execute agents.
See README.md for platform installation and a mock-provider quickstart.
>
    require("hive").setup({
      bin = "/absolute/path/to/hive.nvim/bin/hive",
      root = nil,
      follow = true,
      register_server = true,
      peek_lines = 80,
      command_timeout_ms = 5000,
      notify = { done = true, failed = true, started = false,
                 progress = false, orphaned = true },
      dashboard = { width = 0.85, height = 0.8, refresh_ms = 3000 },
      tail = { position = "bottom", height = 0.35 },
    })
<
Root resolves once from the explicit option, $HIVE_ROOT, or cwd/.hive. Changing
Neovim's directory does not switch the board. Call setup with the new root and
full configuration to switch; setup resets unspecified options to defaults.
Old tasks, event cursors, jobs and registration are replaced. Reopen forms.

Periodic polling uses dashboard.refresh_ms even when the dashboard is closed.
Missing boards are not created automatically: run `hive init` first. A board
created after setup is detected by polling.

==============================================================================
COMMANDS                                                        *hive-commands*

:Hive                                                                  *:Hive*
    Open the task dashboard. Enter: go; t: tail; p: peek; x: kill;
    a: add; P: pause; r: refresh; R: results; q/Escape: close.
:HivePick                                                          *:HivePick*
    Open a task picker. Enter: go; Ctrl-T: tail; Ctrl-P: peek;
    Ctrl-X: kill; Ctrl-R: report. Empty selections are ignored.
:[range]HiveAdd                                                     *:HiveAdd*
    Open a task form after a fresh snapshot. Range lines prefill the prompt.
:HiveResults                                                   *:HiveResults*
    Pick a Markdown task report.
:HiveTail [id]                                                     *:HiveTail*
    Follow a task transcript in a terminal split.
:HivePeek [id]                                                     *:HivePeek*
    Preview live screen, transcript, then report. CLI previews share a
    1.5-second synchronous timeout budget.
:HiveGo [id]                                                         *:HiveGo*
    Switch the current tmux client to agent-ID. Requires Neovim inside tmux.
:HiveKill [id]                                                     *:HiveKill*
    Cancel an active agent and requeue its task.
:HivePause                                                       *:HivePause*
    Toggle scheduler pause. Command failures are reported.
:HiveRefresh                                                   *:HiveRefresh*
    Request a fresh snapshot. Retry a failed initial connection.

Task IDs complete from cached state. Commands with [id] do nothing when the
ID is omitted; dashboard and picker actions supply the selected task ID.

==============================================================================
TASK FORM                                                          *hive-form*

Edit the '#:' header; the first line containing exactly '---' ends the header.
Everything below it is prompt text, preserved including empty and '#:' lines.
Write with :w or Ctrl-S. Escape in normal mode closes the form.

Fields: id, title, provider, deps, priority, worktree, timeout.
IDs use letters/digits/underscores/hyphens and start with a letter or digit.
Dependencies are separated by commas or whitespace. A task cannot depend on
itself. Priority is a non-negative integer; timeout is positive seconds;
worktree is true or false. Providers: mock, claude, codex, gemini, aider.

The ID suggestion uses a fresh snapshot. If another client takes that ID,
submission fails safely. Choose another ID or reopen the form. Legacy backends
without capabilities.atomic_add cannot submit tasks from the plugin.

==============================================================================
EVENTS                                                           *hive-events*

The follower streams journal events and reconnects after two seconds. Optional
push delivery uses HIVE_ON_EVENT=hive-push and root/nvim.server. Push targets
the most recently registered editor; other editors can use followers. Set
follow=false for push-only operation with periodic journal recovery.

Historical events in the initial snapshot are not emitted. Subsequent events
are delivered once in sequence order; gaps are recovered from the append-only
journal. Snapshot revisions never advance the delivered-event cursor.
>
    vim.api.nvim_create_autocmd("User", {
      pattern = "HiveEvent",
      callback = function(a) print(a.data.type, a.data.task) end,
    })
<
Public API: require("hive").open(), pick(), results(), add(lines), tail(id),
peek(id), go(id), kill(id), toggle_pause(), refresh(callback), statusline(),
on_event(event), on_event_json(json, optional_root).

refresh callback receives (snapshot, error); snapshot is nil on failure.
The cached statusline reports counts or "hive: disconnected" on failure.

==============================================================================
TROUBLESHOOTING                                          *hive-troubleshooting*

Run :checkhealth hive. Use the bundled CLI and an initialized root. On macOS,
GNU coreutils' gnubin directory must be on PATH for the timeout executable.
If push registration fails, the default follower still works. The journal
must remain append-only; rerun setup after resetting a board.

Use one board per tmux server: agent session names use task IDs. Real providers
and interactive behavior require manual verification; this is experimental.
